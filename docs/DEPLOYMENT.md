# Setup and deployment boundaries

## Local development
1. Install Python 3.11+ and create a virtual environment.
2. Install dependencies: python -m pip install -r requirements.txt
3. Run: python -m scripts.run_pipeline --sessions 2500 --seed 42 --days 90
4. Open Streamlit: streamlit run dashboard/app.py
5. Run tests: python -m pytest -q

## GitHub Actions
CI on pushes and PRs installs dependencies, runs unit tests, builds synthetic marts, tests dbt constraints and checks a generated aggregate JSON snapshot. Review the workflow run before claiming a green build.

## Static dashboard
The self-contained gallery at dashboard/index.html is an illustration. A public Pages website, if enabled, can serve the static gallery; it does not run DuckDB, dbt or Streamlit. The optional local dashboard/metrics.json is generated by the pipeline and ignored by Git.

## Production expansion (not implemented)
Partitioned Parquet or cloud object storage, ingestion queues, upstream CDC, auth/RBAC, PII protection, source contract versions, data freshness SLAs, incident alerts, warehouse cost monitoring, formal load tests, and enterprise CI secrets are separate follow-on work.
